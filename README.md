# 飞书 Codex 遥控器 Skill

[English](README_EN.md)

一个可 DIY 的本地 Codex 手机助手，可以按个人工作方式自由配置。一句话开始安装，环境已准备好时，目标约 15 分钟完成首次连接；连接后，可以继续调整，让它更适合你的用法。

想在安卓或华为手机上远程使用 Codex，或者不想每次派任务都先等 ChatGPT 重连？这个小工具提供了一条简单路径：把飞书变成 Codex 遥控器，不需要把本地项目暴露到公网，也不需要额外搭建管理后台。

你可以在飞书里连续给 Codex 发任务，不用等上一条完成再输入。要让任务真正执行并返回结果，电脑和 Codex 必须保持运行；它们关闭时仍然可以接收新消息，消息会进入待处理状态，下次打开 Codex 后再按顺序处理。远程产生的截图、Excel、PDF 等文件也可以通过飞书查看或下载。

它会尽可能自动配置，但不是完全托管式服务。首次连接可能因飞书账号、权限审批或电脑环境不同，需要你扫码、确认，或按 Codex 提示处理少量卡点；完成这次配置后，你可以继续用对话指令把它改造成适合自己的工具。

## 它能帮你做什么

- 在手机上远程检查代码、修改文件、运行测试或整理资料；
- 连续发送多条想法和要求，让 Codex 按顺序处理；
- 电脑不在身边时，也能直接通过飞书把任务交给 Codex，不必先记在备忘录里；
- 简短结果直接回复；截图会作为飞书图片直接显示，明确交付的 PDF、Excel 会作为群聊附件发送，长教程和复杂排版则使用私有飞书文档；
- 一个飞书群固定对应一个本地项目，修改群名不会影响连接；
- 通过对话指令查看消息状态、Codex 用量，或设置后续提醒。

这些是开箱即用的基础体验，不是固定的功能上限。安装后，你仍然可以直接和 Codex 对话，让它调整现有行为、增加适合自己的功能。例如：

- 每天整理并推送行业新闻；
- 在明确团队租户、群成员和本地权限边界后，让同事通过 @ 机器人提交工作问题；
- 为不同项目群设置各自的回复格式、巡检内容、工作约定和定时任务。

这些属于按需 DIY 的扩展，不是默认开启的功能；Codex 会在对应项目、权限和安全边界内完成修改与验证。

## 开始前需要什么

- 一台已经安装并登录 Codex 的 Windows 或 Mac 电脑；
- 一个可以正常使用的飞书账号。首次使用**默认并推荐个人版飞书**，风险最低，也通常不需要团队管理员介入。只有当你的明确目标就是接入某个公司飞书账号下的工作群，并且你接受组织可见性和管理员审批等影响时，才在该团队账号中配置；
- 一个已在 Codex 中创建、希望通过飞书远程管理的本地项目。

Windows 可直接试用。macOS 版本目前为 Beta，建议首次安装时留意 Codex 给出的系统提示。需要 Python 3.10 或更高版本；如果电脑上没有，Codex 会先说明并协助处理。

## 安装

### 第一步：把 Skill 交给 Codex

复制下面这句话发给 Codex：

> 安装 https://github.com/ChiyuSONG/feishu-codex-remote 仓库中的 `skill/feishu-codex-remote` Skill。

也可以手动将 [`skill/feishu-codex-remote`](skill/feishu-codex-remote) 复制到 Codex Skills 目录，然后重启或刷新 Codex。不要把整个仓库复制成一个 Skill。

### 第二步：一句话连接飞书

在 Codex 中找到你想通过飞书远程管理的项目，打开其中一个对话，发送：

> 使用 `$feishu-codex-remote`，把当前项目连接到我的飞书。尽可能自动完成，只在需要我扫码、登录或授权时提醒我。

**安装时：本地 Codex 怎么设置**

建议使用 **GPT-6 Astra**，并**强烈建议开启 Full Access**，减少安装过程中的权限询问。推理等级和快速模式（Fast mode）按需选择，不作硬性要求。

**连接后：飞书任务默认用什么配置**

- 新项目默认使用 **GPT-6 Astra**（`gpt-6-astra`）和 **Full Access**；推理等级、快速模式沿用本机 Codex 配置。已有项目的显式模型、推理和加速设置保留。
- 各项目可通过对话指令单独调整，按任务难度和额度需求选择，不必与安装时相同。

> **Full Access 风险提示——安装和远程使用均适用：它允许读写本机文件、执行命令，误操作或恶意指令可能影响项目外的数据。请只在可信电脑和项目中使用。可通过对话指令改为“仅项目权限”或“逐次审批”，但部分操作可能需要回到电脑处理；为保持远程任务顺畅，仍强烈建议使用 Full Access。**

**套餐建议**

**Plus 即可使用**；频繁跑长任务或管理多个项目，推荐 **Pro 20×**，额度更从容。档位与额度以 [OpenAI 官方说明](https://learn.chatgpt.com/docs/pricing) 为准。

剩下的配置由 Codex 完成。

**配置期间请尽量不要操作电脑**：Codex 会通过 CUA（电脑界面自动操作）配置浏览器和飞书，可能暂时接管鼠标和键盘；需要扫码、登录或授权时再按提示接手。

你通常只需要按提示：

1. 扫码或登录飞书；
2. 确认开发者后台当前选中的是个人账号；这是首次使用的默认选择。如果 Codex/CUA 发现团队或企业账号，会在创建应用前暂停并请你切换。只有你的需求明确指向该账号下的工作群，并且你确认接受管理员审批和组织可见性等影响后，它才会继续；
3. 同意消息、图片/文件和私有文档所需权限；
4. 必要时复制一次飞书应用凭证；
5. 首次启动时确认一次 Codex 的安全提示。

Codex 会先向绑定群发送一张真实测试图片；只有你能在飞书里看到它，连接才算成功，随后群里会收到欢迎消息。缺少权限时，Codex 会在这一步直接请你补充授权，不会把“发送失败”当作安装完成。

## 在飞书里怎么用

直接像平时和 Codex 对话一样发消息：

- `检查项目里最近的改动并运行测试。`
- `我接下来会连续发三条要求，全部收到后按顺序处理。`
- `把完整结果整理成飞书文档。`
- `先记录这件事，等我补完信息再开始。`

你可以在一条任务处理期间继续发送新消息，它们会排队等待。电脑或 Codex 关闭时任务不会执行，但消息不会丢失；下次打开 Codex 后会继续处理。

在上一项任务处理期间连续发送的多条消息，可能会合并为一轮处理，但每条要求都会保留。开头加 `*` 可单独排队处理；加 `#` 可继承主线上下文，独立并行处理本条消息。后续普通消息仍回主线。

## 自动巡检是什么

每连接一个新项目，默认会为该项目启用每小时一次的自动巡检，除非你在安装时选择关闭。它会确认连接正常、补拉遗漏或积压的消息。电脑或 Codex 关闭时不会巡检；再次打开 Codex 时，后台连接会先恢复并补拉消息，不必等到下一次巡检。

同一台电脑复用同一个飞书机器人时，**项目状态分别报告，共用信息集中报告**：

- **第一个项目**：首次巡检介绍用途，之后默认报告下面三行；
- **后续新项目**：从首次巡检起，只报告第一行状态，不重复发送用量和提示。

1. 当前有没有待处理、处理中或失败的消息；如果任务正在执行，还会显示已运行多久和最近一条安全进展；
2. Codex 的 5 小时和 7 天额度还剩多少；
3. 可以通过对话指令修改巡检、设置提醒或增加其他用法。

已有的巡检定制保持不变。提醒和其他 DIY 功能只在你指定的对话中设置，不会自动复制到新项目。

例如可以说：

- `只在发现积压、失败或异常时通知我。`
- `巡检时不要报告 Codex 用量。`
- `把自动巡检改成每两小时一次。`
- `暂停自动巡检。`

每次巡检都会发起一次轻量 Codex 运行并消耗少量相应额度，不需要时可以暂停。

提醒并不会默认创建。需要时，可以把巡检变成你自己的小工具。例如：

> 从明天上午 10 点开始，每次巡检都提醒我提交材料，直到我说已经完成。

Codex 会记住这件事，并在到达时间后的巡检中持续提醒；完成后直接说 `材料已经提交，停止提醒`。你也可以通过对话指令设计其他巡检用法，不需要遵循固定格式。

这类提醒依赖电脑、Codex 和自动巡检，并不是准点闹钟。严格准点的事情请使用飞书日历或手机闹钟。

## 常见问题

### 安卓或华为手机怎么远程使用 Codex？

在电脑上完成本工具的安装和飞书连接后，用手机上的飞书向绑定群发送任务即可，结果也会返回飞书。手机需能正常使用飞书；电脑和 Codex 需保持运行并能正常连接服务。

### 使用飞书后，还需要在手机上安装 ChatGPT 吗？

不需要。通过本工具派任务、收结果只需使用手机上的飞书，不依赖 ChatGPT 手机 App。这并不免除电脑端的 Codex 安装、登录和网络要求。

### 电脑和 Codex 需要一直开着吗？

如果希望任务及时处理，就需要让电脑开机，并保持 Codex 运行。电脑或 Codex 关闭后，飞书仍会接收新消息并把它们保留为待处理，但不会执行任务；下次打开 Codex 后才会继续处理。

### 修改飞书群名会断开连接吗？

不会。连接不依赖群名。

### 可以连接多个项目吗？

可以。建议每个项目使用一个单独的飞书群，避免上下文混在一起。

### 发错消息后，可以直接编辑或撤回吗？

不要依赖编辑或撤回。当前版本只把新消息作为可靠指令：编辑或撤回不会被当成对已入队任务的更正或取消。请另发一条新消息说明更正，例如：`更正上一条：只修改 README，不改代码。` 如果上一项任务已经开始，新消息会排到下一轮处理，不能实时改变正在运行的那一轮，也不会自动撤销已经完成的操作。

### 回复一定会变成飞书文档吗？

不会。简单回复直接发在群里；较长或结构复杂的内容才使用私有飞书文档。截图会直接显示在群里；Codex 在回复中明确交付的 PDF、Excel 会作为可下载的群聊附件发送，也可在完整文档中保留备用链接。发送失败时回复会明确提示，不会静默丢失。

## 卸载

不需要运行命令，直接对 Codex 说：

> 卸载飞书 Codex 遥控器。保留飞书对话和文档，先告诉我会移除什么，然后自动完成。

Codex 会先列出准备移除的内容，确认后再卸载，不影响其他 Codex 任务，也不会删除飞书对话、群聊或已经生成的飞书文档。

默认保留一份恢复备份。如果还要删除本地凭据、缓存和历史状态，请明确补充：`同时清除全部本地数据`。

## 隐私与安全

- 默认 Full Access 只代表本地执行能力，不代表可以跨项目工作；可随时通过对话指令降为仅项目权限或逐次审批；
- 不需要把本地项目开放到公网；
- 飞书凭证保存在仓库之外；
- 生成的飞书文档会关闭公开链接分享并验证设置；
- 每个群只连接你明确选择的本地项目；
- 仓库不保存你的凭据、对话、项目路径或运行记录。
