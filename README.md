# 飞书远程 Codex

[English](README_EN.md)

把飞书变成本地 Codex 的手机入口：一句话开始安装，环境已准备好时，目标约 15 分钟完成首次连接。

你可以在飞书里连续给 Codex 发任务，不用等上一条完成再输入。要让任务真正执行并返回结果，电脑和 Codex 必须保持运行；它们关闭时仍然可以接收新消息，消息会进入待处理状态，下次打开 Codex 后再按顺序处理。远程产生的截图、Excel、PDF 等文件也可以通过飞书查看或下载。

如果你想知道“安卓或华为手机怎么远程使用 Codex”，或者希望用飞书连接本地 Codex、减少对 ChatGPT/Codex 手机端的依赖，这个小工具提供了一条简单路径：不需要把本地项目暴露到公网，也不需要额外搭建管理后台。

## 它能帮你做什么

- 在手机上远程检查代码、修改文件、运行测试或整理资料；
- 连续发送多条想法和要求，让 Codex 按顺序处理；
- 电脑不在身边时，先把任务发到飞书，不必另外记在微信或备忘录；
- 简短结果直接回复；截图会作为飞书图片直接显示，明确交付的 PDF、Excel 会作为群聊附件发送，长教程和复杂排版则使用私有飞书文档；
- 一个飞书群固定对应一个本地项目，修改群名不会影响连接；
- 用自然语言查看消息状态、Codex 用量，或设置后续提醒。

这些是开箱即用的基础体验，不是固定的功能上限。安装后，你仍然可以直接和 Codex 对话，让它调整现有行为、增加适合自己的功能，或为不同飞书群设置不同的回复方式、巡检内容和工作约定。Codex 会在对应项目、权限和安全边界内完成修改与验证，不需要你先学会配置文件或命令。

## 开始前需要什么

- 一台已经安装并登录 Codex 的 Windows 或 Mac 电脑；
- 一个可以正常使用的个人飞书账号。**务必在个人账号下创建应用**；团队/企业账号通常需要管理员审批。除非你明确了解并同意在团队账号中创建，否则不要使用团队账号；
- 一个准备让 Codex 处理的本地项目文件夹。

Windows 可直接试用。macOS 版本目前为 Beta，建议首次安装时留意 Codex 给出的系统提示。需要 Python 3.10 或更高版本；如果电脑上没有，Codex 会先说明并协助处理。

## 安装

### 第一步：把 Skill 交给 Codex

把本仓库地址发给 Codex，并说：

> 安装这个仓库中的 `skill/feishu-codex-remote` Skill。

如果仓库是 Private，请先确保 Codex 所在电脑已经登录并有权访问这个 GitHub 仓库。

也可以手动将 [`skill/feishu-codex-remote`](skill/feishu-codex-remote) 复制到 Codex Skills 目录，然后重启或刷新 Codex。不要把整个仓库复制成一个 Skill。

### 第二步：一句话连接飞书

在 Codex 中打开准备连接的本地项目，然后发送：

> 使用 `$feishu-codex-remote`，把当前项目连接到我的飞书。尽可能自动完成，只在需要我扫码、登录或授权时提醒我。

> **安装前提醒：** 默认远程模型为 **GPT-6 Astra**（`gpt-6-astra`）；已有的显式模型、推理等级与 Priority/Fast 开关保持原样。建议将本地 Codex 设为 **Full Access**，以免安装和后续远程任务反复暂停询问权限。ChatGPT Plus 已可正常安装和使用；如果你会频繁运行长任务或同时连接多个项目，Pro 5× 或更高额度会更从容，Pro 档位主要增加 Codex 可用额度，并不会让同一个模型变得更聪明。接下来的约 15 分钟，Codex 会通过 CUA（电脑界面自动操作）配置浏览器和飞书，可能暂时接管鼠标和键盘，请尽量不要同时操作电脑；需要扫码、登录或授权时再按提示接手。Full Access 权限较高，请只在你信任的电脑和项目中使用，之后可随时用自然语言改成“仅项目权限”或“逐次审批”。

剩下的配置由 Codex 完成。你通常只需要按提示：

1. 扫码或登录飞书；
2. 确认开发者后台当前选中的是个人账号；如果 Codex/CUA 发现团队或企业账号，会在创建应用前暂停并请你切换。只有你明确同意在团队账号中创建、并接受管理员审批等影响后，它才会继续；
3. 同意消息、图片/文件和私有文档所需权限；
4. 必要时复制一次飞书应用凭证；
5. 首次启动时确认一次 Codex 的安全提示。

Codex 会先向绑定群发送一张真实测试图片；只有你能在飞书里看到它，连接才算成功，随后群里会收到欢迎消息。缺少权限时，Codex 会在这一步直接请你补充授权，不会把“发送失败”当作安装完成。

## 在飞书里怎么用

直接像平时和 Codex 对话一样发消息：

- `检查项目里最近的改动并运行测试。`
- `我接下来会连续发三条要求，全部收到后按顺序处理。`
- `把完整结果整理成飞书文档。`
- `先记录这件事，等我补完信息再开始。`

你可以在一条任务处理期间继续发送新消息，它们会排队等待。电脑或 Codex 关闭时任务不会执行，但消息不会丢失；下次打开 Codex 后会继续处理。

在上一项任务处理期间连续发送的多条消息，可能会合并为一轮处理，但每条要求都会保留。开头加 `*` 可单独排队处理；加 `#` 可继承主线上下文，独立并行处理本条消息。后续普通消息仍回主线。

## 自动巡检是什么

电脑和 Codex 运行时，默认每小时检查一次，主要做三件事：确认连接正常、查找遗漏或积压的消息、报告 Codex 用量。电脑或 Codex 关闭时不会巡检。

第一次巡检会完整介绍用途。以后如果你没有修改，它只会简短告诉你：

1. 当前有没有待处理、处理中或失败的消息；如果任务正在执行，还会显示已运行多久和最近一条安全进展；
2. Codex 的 5 小时和 7 天额度还剩多少；
3. 巡检内容可以直接用自然语言调整。

例如可以说：

- `只在发现积压、失败或异常时通知我。`
- `巡检时不要报告 Codex 用量。`
- `把自动巡检改成每两小时一次。`
- `暂停自动巡检。`

每次巡检都会发起一次轻量 Codex 运行并消耗少量相应额度，不需要时可以暂停。

巡检也可以变成你自己的小工具。例如，你可以说：

> 从明天上午 10 点开始，每次巡检都提醒我提交材料，直到我说已经完成。

Codex 会记住这件事，并在到达时间后的巡检中持续提醒；完成后直接说 `材料已经提交，停止提醒`。你也可以用自然语言设计其他巡检用法，不需要遵循固定命令。

这类提醒依赖电脑、Codex 和自动巡检，并不是准点闹钟。严格准点的事情请使用飞书日历或手机闹钟。

## 常见问题

### 电脑和 Codex 需要一直开着吗？

如果希望任务及时处理，就需要让电脑开机，并保持 Codex 运行。电脑或 Codex 关闭后，飞书仍会接收新消息并把它们保留为待处理，但不会执行任务；下次打开 Codex 后才会继续处理。

### 修改飞书群名会断开连接吗？

不会。连接不依赖群名。

### 可以连接多个项目吗？

可以。建议每个项目使用一个单独的飞书群，避免上下文混在一起。

### 发错消息后，可以直接编辑或撤回吗？

不要依赖编辑或撤回。当前版本只把新消息作为可靠指令：编辑或撤回不会被当成对已入队任务的更正或取消。请另发一条新消息说明更正，例如：`更正上一条：只修改 README，不改代码。` 如果上一项任务已经开始，新消息会排到下一轮处理，不能实时改变正在运行的那一轮，也不会自动撤销已经完成的操作。

### 回复一定会变成飞书文档吗？

不会。简单回复直接发在群里；较长或结构复杂的内容才使用私有飞书文档。截图会直接显示在群里；Codex 在回复中明确交付的 PDF、Excel 会作为可下载的群聊附件发送，也可在完整文档中保留备用链接。发送失败时回复会明确提示，不会静默丢失。

## 卸载

不需要运行命令，直接对 Codex 说：

> 卸载飞书远程 Codex。保留飞书对话和文档，先告诉我会移除什么，然后自动完成。

Codex 会先列出准备移除的内容，确认后再卸载，不影响其他 Codex 任务，也不会删除飞书对话、群聊或已经生成的飞书文档。

默认保留一份恢复备份。如果还要删除本地凭据、缓存和历史状态，请明确补充：`同时清除全部本地数据`。

## 隐私与安全

- 默认 Full Access 只代表本地执行能力，不代表可以跨项目工作；可随时通过自然语言降为仅项目权限或逐次审批；
- 不需要把本地项目开放到公网；
- 飞书凭证保存在仓库之外；
- 生成的飞书文档会关闭公开链接分享并验证设置；
- 每个群只连接你明确选择的本地项目；
- 仓库不保存你的凭据、对话、项目路径或运行记录。
